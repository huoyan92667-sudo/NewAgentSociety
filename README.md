# 新 Agent 独立项目

这个目录承载新版通用 Agent 和第一项真实能力——餐厅推荐。它拥有独立的源码、
运行入口、配置、数据目录、数据库升级记录、测试和开发文档，不再依赖旧
`yelp_agent` 包里的 Agent、排序器或会话系统。

## 当前状态

新版代码已经进入独立目录，通用对话、工具选择、会话记忆、数据库、餐厅要求融合、
硬过滤、固定 14 项排序、长尾评论查询和最终回答都只从 `new_agent` 导入。当前离线
自动测试共 153 条，已经全部通过。独立 PostgreSQL 已升级到最新版本；现有 624,746
个评论片段和向量也已经导入独立 Qdrant，同时支持按意思和按关键词检索。

每一批修改都必须同时更新：

- [开发过程记录](docs/development-log.md)：记录做了什么、为什么、结果和遗留问题；
- [实验索引](docs/experiments/README.md)：记录真实输入、输出、耗时、词元和前后对比；
- [项目整体过程](项目整体过程.md)：在一个文件中说明架构、数据、实验、数据库和完成度；
- 本文件：只保留当前已经可以使用的能力和准确运行方法。

旧代码不会进入独立仓库；旧文档原文统一保存在 `docs/history/legacy-snapshots/`，只用于
追溯。真实多轮、单店事实、固定证据、长尾评论和闲聊切换已经从新目录通过验证。

## GitHub 仓库包含什么

GitHub 包含独立源码、数据库升级、配置示例、153 条自动测试、召回测评、2,142 条教师
标签和 2,142 条学生训练/验证/测试样本。它不包含完整评论、评论向量、Qdrant、
PostgreSQL、用户画像、500 家完整特征数据库和模型权重。全新克隆后不能在没有这些外部
数据的情况下直接运行真实推荐，具体规模和迁移状态见[项目整体过程](项目整体过程.md)。

## 收到问题以后怎样运行

```text
用户原话和最近对话
        ↓
主模型决定直接回答还是调用工具
        ↓
如果是完整推荐：融合本轮要求、会话旧要求、长期画像和场景默认值
        ↓
程序按必须满足的条件过滤餐厅
        ↓
程序按有先后顺序的软偏好排序并附上正反评论证据
        ↓
主模型读取固定前五和证据，写出最终回答
        ↓
保存本轮问答、必要状态、前十对象编号、消耗和耗时
```

如果用户问“第三家服务怎么样”，主模型从当前工作记忆取回第三家的真实编号，然后
选择查固定 14 项证据或查具体评论；不会重新跑一轮完整推荐。更详细说明见
[当前系统说明](docs/current-system.md)。


## 独立完成的判断标准

只有同时满足下面条件，才算真正从旧 Agent 独立出来：

1. 只把 `new_agent/src` 加入 Python 路径时能够启动；
2. 新源码中不存在对 `yelp_agent` 的导入；
3. 所有正式数据都从 `new_agent/data` 或明确配置的外部模型目录读取；
4. PostgreSQL、Qdrant、数据库升级和命令行入口均由本目录管理；
5. 餐厅推荐、单店追问、修改要求、闲聊切换和旧对话取回全部通过；
6. 实验结果包含真实回答、耗时、词元和迁移前后差异。

前五项在线运行边界已经达到；第六项已有真实记录但正式测评覆盖仍不足。当前不是整个
规划的最终完成版，未完成内容以[项目整体过程](项目整体过程.md)为准。

## 文档纪律

代码修改不能脱离记录单独提交。每一个功能批次至少记录：

1. 修改前的问题；
2. 修改内容；
3. 验证输入和验证方法；
4. 修改后的真实结果；
5. 耗时和词元变化；
6. 尚未解决的问题；
7. 对应 Git 提交。

整体过程统一记录在[项目整体过程](项目整体过程.md)；历史原文、失败尝试和旧新对比保留
在 [迁移前快照](docs/history/) 中，不允许只写
“效果变好”而不保留问题、输入、输出和数字。

## 本地启动

以下命令都在 `new_agent` 目录执行：

```powershell
python -m pip install -e ".[dev]"
docker compose -f infra/docker-compose.yml up -d
python -m alembic -c src/new_agent/persistence/alembic.ini upgrade head
python run/verify_runtime_data.py
python run/import_review_index.py
python run/chat.py "给我推荐一家安静、服务好、停车方便的牛排店" `
  --user-id "真实用户编号" `
  --session-id "独立会话编号" `
  --stream
```

`import_review_index.py` 不会重新生成评论向量，也不会默认删除已有集合。同一份片段和
向量已经完整导入时，它会核对文件指纹与库内条数后直接返回；只有尚未导入时才写入。

模型、数据库、本地向量模型和评论库地址写入 `.env`；字段示例见 `.env.example`，
真实密钥不会进入 Git。
