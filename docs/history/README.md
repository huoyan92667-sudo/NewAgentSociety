## 整个演进过程

1. 最初用历史行为预测下一次去哪家，并建立旧排序测评；
2. 建立用户长期画像和商家画像；
3. 尝试传统混合排序、学习排序和 Query-aware 排序；
4. 建立受控工具、会话状态和旧版 Agent 外壳；
5. 重新定义目标为“本轮问题、会话、画像、场景融合后的推荐”；
6. 统一硬条件与软偏好结构，加入六个场景和四路融合；
7. 建立固定餐饮类别、商家事实、距离、营业时间和结构化硬过滤；
8. 把评论切成完整语义片段，建立向量与关键词混合检索；
9. 建立正反证据、时间与数量聚合，并比较三种评论判断方法；
10. 用教师模型生成 2,142 条标签，构造 Qwen3 4B 的训练、验证和测试集；
11. 在服务器离线计算 500 家餐厅的 14 项评论画像和证据；
12. 建立通用 Agent 循环、工具调用前后检查、PostgreSQL、用量统计和上下文压缩；
13. 把完整餐厅推荐作为一个受控工具接入，另外提供商家事实、固定证据和长尾评论工具；
14. 将正式在线代码抽离到当前独立项目，并单独建立 PostgreSQL 与 Qdrant；
15. 用真实多轮和长尾追问验证，再根据失败记录修复重复工具调用。

上面是导航，不代替原始实验。涉及具体数字、真实输出和失败原因时，应回到对应原文。
